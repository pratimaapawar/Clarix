User Manual

Step-by-step guide to analysing transactions, with ready-to-run demo examples.

Clarix scores a financial transaction for fraud risk and explains, in plain language, exactly why it reached that verdict. It supports Transfer, Cash-out and Cash-in transactions. Each one is reviewed on a confirmation screen before it is analysed.

1 · Analyse a single transaction
2 · Transaction types
Type What it is What to enter How it is scored
TRANSFER Money moved from one account to another account. Amount, origin balance before/after, destination balance before/after. ML ensemble + balance rules.
CASH_OUT Cash withdrawal from an account (ATM / agent / teller). Amount, account balance before/after. No destination account. ML ensemble + balance rules.
CASH_IN Cash deposited into an account. The balance should go up by the amount. Amount, account balance before/after. No destination account. Balance rules only. The ML model was not trained on deposits.

5 · Reading the result
Tier Meaning
HIGH Score ≥ 80, or any rule check failed. Banner: FRAUD DETECTED.
MEDIUM Score 40–79. Banner: FLAGGED FOR REVIEW.
LOW Score below 40 and all rule checks passed. Banner: TRANSACTION LEGITIMATE.

Under the verdict, Why: Top Factors lists the rules that fired (tag RULE) and the features that raised or lowered the risk. View Full Details shows the raw fields, computed features and the score from each model.

About Clarix

How the system detects and explains fraud.

Clarix combines an ensemble of machine-learning models — Isolation Forest, XGBoost, and LightGBM — with explainable AI (SHAP) and a rule-based layer that verifies account-balance consistency. Each transaction is scored by all three models; SHAP attributes the result to specific features, and the rule layer catches balance anomalies the models might miss. The dashboard then presents a single risk score alongside the plain-English factors behind it, so a reviewer can understand and trust every decision.
